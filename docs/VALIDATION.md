# Tatsächlich geprüfter Stand

Version 1.1.2, geprüft am 16. Oktober 2026 in der Cloud-Entwicklungsumgebung, mit Node.js 24 und System-Chromium.

- Die Umgebung wurde mit `npm ci --cache /tmp/telematik-npm-cache --no-audit --no-fund` eingerichtet. Für diesen Stand wurde Vitest mit `npm install --save-dev 'vitest@^4.1.11' --cache /tmp/telematik-npm-cache --no-fund` aktualisiert; Paketdefinition und Lockdatei sind gemeinsam gespeichert.
- `npm run build`: erfolgreich; selbstständige HTML-Datei mit eingebetteten Skripten, Styles und Schriftdateien.
- `npm test`: **122 Tests bestanden**, darunter Referenzwerte für alle IPv4-Präfixe von /0 bis /32, Masken, FLSM, beidseitiger Netzvergleich, ungültige Eingaben, Fragenbestand, geführte Inhalte, Abschlussregeln, Antwortformate, aufgabenspezifische Hinweise, URL-Routen, Routerauswahl, PAT-Zuordnung, Fortschrittsimport und Zusammenführen älterer Sicherungen. Ein zusätzlicher Test prüft, dass unbekannte persönliche Felder beim Import verworfen werden.
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e -- --workers=2`: **20 Browsertests bestanden**. Abgedeckt sind alle 59 Lektionsschritte, richtige/falsche Verständnisantworten, Abschlüsse, genaue Position nach Reload, Browsernavigation, Trainer, Quiz/Prüfung, Fehlerwiederholung, Import/Export, beide Themes, schmale Ansichten, Routing/PAT, Fokus-Timer und Simulationstabs. Der Produktions-Test lädt nur die Einzeldatei, speichert über «Offline-Datei» eine saubere Kopie, prüft leeren Lernenden-DOM sowie eingebettete Skripte/Styles und startet die Kopie ohne zusätzliche Asset-Anfragen. Eine alte Sicherung öffnet inzwischen korrigierte Fehler nicht erneut. Die produktive Content Security Policy blockiert eine Test-Datenanfrage mit der Direktive `connect-src`; Referrer- und Suchmaschinen-Metadaten sind geprüft.
- Der erste Browserlauf dieses Stands deckte einen mehrdeutigen Testselektor für Zahlenantworten sowie eine zeitliche Lücke vor der Navigationswarnung auf. Nach Korrektur von zugänglichen Antwortnamen, Selektoren und synchroner Registrierung der aktiven Runde wurden die beiden betroffenen Tests je achtmal wiederholt: **16 Wiederholungen bestanden**. Anschliessend bestand der gesamte Browserlauf.

- Automatische WCAG-A/AA-Prüfungen mit axe: keine gemeldeten Verstösse auf den sieben geprüften Hauptseiten sowie repräsentativen geführten Lektionen in beiden Farbschemata. Auch die produktiven Routing-/PAT-Werkzeuge wurden geprüft. Das ist keine vollständige manuelle Barrierefreiheitszertifizierung.
- Produktions-HTML über einen lokalen HTTP-Server geladen, danach Netzwerk offline geschaltet: Trainer, Themewechsel, Begriffssuche, geführte Lektionen und interaktive Werkzeuge funktionieren weiter. Alle Schriften/Assets sind eingebettet; nur die HTML-Dokumente wurden angefordert. Fortschritt und die genaue Lektionsposition bleiben nach Reload erhalten. Keine beobachteten JavaScript-Laufzeitfehler.
- Direkte Navigation zu `file://` wurde durch die Richtlinie des Cloud-Browsers blockiert. Doppelklick-Öffnen auf einem eigenen Rechner ist deshalb hier nicht separat bestätigt. Bei restriktiven Schulgeräten kann die App mit `npm run preview` lokal über HTTP genutzt werden.
- `npm run format:check` und `git diff --check`: erfolgreich.
- `npm audit --omit=dev`: **keine gemeldeten Schwachstellen**. Das vollständige Audit meldet weiterhin drei hohe Einträge derselben Build-Abhängigkeit (`braces` über `micromatch` und `vite-plugin-singlefile`), ohne verfügbaren automatischen Fix. Diese Pakete werden nur zum Bauen verwendet und nicht in die statische App eingebunden. Die zuvor gemeldeten Vitest-/Worker-Einträge sind durch das Testwerkzeug-Update behoben. Das Audit ist keine vollständige Sicherheitsprüfung.
- Datenschutzreview: erreichbare Git-Dateiversionen auf private Dateinamen, E-Mail-Adressen im Inhalt und gängige Schlüssel-/Tokenmuster geprüft; keine entsprechenden Funde. Dokumentations-Screenshots enthalten keine Text-Metadaten und zeigen nur die Lernoberfläche. Öffentliche Commit-Absender sind separat zu behandeln; Hinweise stehen in [PRIVACY.md](PRIVACY.md).

Nicht geprüft: Firefox/Safari, aktuelle Videoverfügbarkeit, Inhalt der nicht bereitgestellten 164 Originalseiten, Moodle-Integration oder ein öffentlicher Hostingbetrieb. GitHub Actions für Tests und eine getrennte Pages-Veröffentlichung sind eingerichtet; die Veröffentlichung selbst wurde hier nicht aktiviert oder verifiziert. Die Cloud-Netzwerkverbindung zu GitHub Pages und der GitHub-API wird mit einem Proxy-Tunnelfehler verweigert; dies belegt keinen Fehler des tatsächlichen Website-Servers. Die obigen Ergebnisse stammen aus dieser Umgebung, nicht aus einem unabhängig beobachteten Actions-Lauf.
